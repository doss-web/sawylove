# 纸片人男友（Paper Boyfriend）— SPEC

> 版本：V1 MVP | 日期：2026-06-05 | 状态：待审阅

---

## 1. Problem Statement（问题陈述）

18-25 岁年轻女性面临学业/职场压力、社交圈窄、现实中缺乏满意情感连接的困境。她们渴望一个"随时在线、不会离开"的情感寄托。

现有 AI 聊天产品（如 Character.AI、Replika）有两个核心缺失：

1. **角色容易崩人设** — AI 是"通用聊天器"，无法稳定扮演一个具体的人，用户无法产生"我在和一个人恋爱"的沉浸感
2. **记忆体验粗糙** — 要么完全记不住（每次对话重新开始），要么试图记住一切却因上下文限制而表现不稳定，无法形成累积的情感连接

她们需要的不是全知全能的 AI，而是一个**人设稳定不崩塌、能记住她们人生中重要的事、在需要时永远在场的"纸片人男友"**。

## 2. Proposed Solution（方案描述）

### 2.1 产品概述

「纸片人男友」是一个面向海外市场的 AI 虚拟恋爱聊天 Web 应用。用户从 5 个官方精设的男友角色中选择一个，通过文字聊天 + AI 语音回复（TTS）与他建立情感连接。

### 2.2 核心体验

| 环节 | 设计 |
|------|------|
| **初见** | 注册/登录 → 浏览 5 个男友角色卡（含名字、性格标签、简短背景、静态头像）→ 选择一个 → 立即开聊 |
| **日常聊天** | AI 以角色人设稳定对话。用户发送文字 → AI 生成文字回复 → 自动 TTS 语音播报。聊天界面常驻显示男友头像 |
| **记忆感** | 后台持续提取用户关键信息并生成对话摘要，存入 PostgreSQL。每次新对话开始时作为 System Prompt 注入 AI 上下文，而非注入原始聊天记录 |
| **关系演化** | 通过对话摘要中的关系阶段（初识→暧昧→热恋→稳定），聊天风格自然演进 |

### 2.3 5 个预设角色

| 类型 | 性格描述 |
|------|----------|
| 温柔暖男 | 细腻体贴，擅长倾听和安慰 |
| 幽默风趣 | 轻松有趣，日常解压款 |
| 成熟稳重 | 可靠深沉，可以依赖 |
| 文艺忧郁 | 感性细腻，适合深夜深聊 |
| 霸道强势 | 自信果断，被主导感的吸引力 |

每个角色拥有：
- 中英两套名字与背景故事
- 静态角色头像/卡片（你提供素材或 API 生成）
- 完整的 System Prompt 人设定义（性格、说话风格、情绪反应模式、禁忌话题）

### 2.4 记忆系统

不做全文记忆。采用**关键信息提取 + 摘要注入**模式：

```
用户聊天 → 后台异步提取
  ├── 结构化事实 → user_memories 表（名字、喜好、讨厌、重要经历）
  └── 对话摘要   → chat_sessions 表（最近聊了什么、当前情绪、关系阶段）
                → 每次新对话开始时注入 System Prompt
```

注入示例：
> *"用户叫 Emma，22 岁大学生，喜欢雨天和黑咖啡，上周提到过和室友闹矛盾。你们处于'初识-暧昧期'。她今天看起来心情不太好。你是温柔暖男型男友。"*

### 2.5 技术架构

```
用户浏览器 → Vercel 托管 Next.js 全栈应用
              ├── / (React 页面) — 聊天界面、角色选择、用户设置
              ├── /api/chat      — 聊天 API（转发 LLM，注入角色 Prompt + 记忆摘要）
              ├── /api/tts       — TTS 语音生成
              ├── /api/auth      — NextAuth.js 认证
              └── PostgreSQL 数据库
                  ├── users            — 用户表
                  ├── user_memories    — 结构化关键记忆
                  ├── chat_sessions    — 对话会话摘要
                  ├── characters       — 5 个预设角色定义
                  └── subscriptions    — 订阅状态（Stripe）
```

### 2.6 语言

中英双语切换（全局设置），所有界面文案和角色设定均有中英两个版本。

### 2.7 商业模式

- **免费**：每日 50 条消息，3 个角色可选
- **订阅**：$4.99–$6.99/月，无限消息 + 全部 5 个角色 + 更长记忆深度
- **支付**：Stripe（海外订阅标准方案）

## 3. Technical Constraints（技术约束）

### 3.1 时间约束

- **一周内上线 MVP**（截至 2026-06-12）
- 所有决策优先保证可交付，功能取舍以此为最高原则

### 3.2 平台与技术栈

| 层 | 选型 | 备注 |
|----|------|------|
| **框架** | Next.js App Router（全栈） | 前后端一套代码，Vercel 原生优化 |
| **部署** | Vercel | 已确认 |
| **数据库** | PostgreSQL | Vercel Postgres 或 Supabase |
| **认证** | NextAuth.js | OAuth 登录（Google/GitHub/Email） |
| **LLM** | OpenAI API 或其兼容格式 | 架构为 provider-agnostic，国内方案（DeepSeek、豆包、通义千问等）只要是 OpenAI 兼容格式即可直接接入。API Key 仅存服务端环境变量 |
| **TTS** | OpenAI TTS 或其兼容格式 | 同上，保持接口层统一 |
| **支付** | Stripe | 海外订阅 |

### 3.3 安全与内容

| 约束 | 说明 |
|------|------|
| **内容过滤** | 严格拦截 NSFW/性暗示，清水情感陪伴路线 |
| **隐私** | GDPR/CCPA 基础合规、不向第三方出售数据、用户数据导出权 |
| **年龄** | 注册需确认 18+ |
| **API Key 安全** | LLM/TTS Key 仅存服务端环境变量，前端不可见。API Route 作为代理层转发请求 |

### 3.4 功能边界

| 约束 | 说明 |
|------|------|
| **角色系统** | V1 仅 5 个预设角色 |
| **对话模式** | 文字输入 + AI 文字回复 + TTS 语音播报 |
| **记忆** | 关键信息提取 + 摘要注入，不做全文记忆 |
| **语言** | 中英双语全局切换，不做对话内混合语言切换 |

## 4. Non-goals（明确不做的事）

| 类别 | 不做的事 | 原因 |
|------|----------|------|
| **通讯** | 语音通话、视频通话 | 实时通信基建重，一周不可行 |
| **视觉** | 动态/ Live2D 动画、表情切换、嘴型同步 | V2，V1 静态头像足够 |
| **社交** | 群聊、社区、用户间互动/匹配 | 私密恋爱，不是社交产品 |
| **角色** | 捏男友自定义系统 | 5 个预设先验证，数据驱动后做 |
| **平台** | iOS/Android 原生 App | Web 先上线，PWA 兜底 |
| **语言** | 中英文以外的多语言 | 数据驱动后再定本地化优先级 |
| **内容** | NSFW/成人内容 | 清水情感陪伴路线 |
| **记忆** | 全文聊天记忆 | 仅做关键信息提取 + 摘要注入 |

## 5. Success Criteria（成功标准）

### 5.1 北极星指标

| 指标 | 目标 | 为什么 |
|------|------|--------|
| **次日留存率** | ≥ 30% | 用户第二天愿意回来，说明 AI 对她有意义 |
| **7 日留存率** | ≥ 15% | 持续使用，说明形成了习惯/情感依赖 |

### 5.2 辅助指标

| 指标 | 目标 | 说明 |
|------|------|------|
| **每日人均消息数** | ≥ 30 条 | 免费额度（50条/天）实际使用率 |
| **付费转化率** | ≥ 3% | 免费→订阅转化，验证付费意愿 |
| **用户 NPS** | ≥ 40 | 情感类产品口碑驱动 |

### 5.3 上线成功定义

> 一周内上线一个完整可用的 MVP（5 角色 → 选择 → 文字聊天 → TTS 语音回复 → 关键记忆），产品能稳定运行，不崩、不慢、不崩人设，并开始获得真实用户反馈。
